## 3. 时间与数据兼容

### 存储格式

统一为 `YYYY-MM-DDTHH:MM:SSZ`。所有时间条件改用 `strftime('%Y-%m-%dT%H:%M:%SZ','now',?)`（`db.SQL_SINCE`）。

这里有两个坑。第一，时间是按字符串比较的，`T` 和空格的排序不同，新旧格式只要混在一起，时段筛选就会出错，所以全仓的 `localtime` 都换掉了，只剩 JSON 导入那一处故意保留。第二，**`CREATE TABLE IF NOT EXISTS` 不会改已有表的列默认值**，老库的 `ts` 默认值仍是 `datetime('now','localtime')`。所以 `save_snapshot` 和 `add_server` 都改成显式写入 UTC 时间（`db.utcnow()`），不依赖默认值。测试专门覆盖了这一点：在老结构的表上写入，结果必须带 `Z`。

### 迁移（`db.migrate_to_utc`）

- 用 `PRAGMA user_version` 标记，只执行一次。
- 有数据时，先用 `sqlite3.Connection.backup` 整库备份到 `mcstatus.db.bak-<时间>`。用 backup 而不是复制文件，是为了带上还在 WAL 里的数据。
- 换算：注册一个 Python 函数 `to_utc`，用 `zoneinfo` 按 `MC_DASH_TZ`（默认 `Asia/Shanghai`）解读旧时间。最初的方案是 SQLite 的 `'utc'` 修饰符，它按进程所在机器的时区换算，在 Docker 里（容器默认 UTC）会算错。用户确认"默认 UTC+8"之后改成了现在这样，和机器时区无关。Windows 和精简版 Docker 镜像都没有系统时区库，所以加了 `tzdata` 依赖。
- `init_db` 的执行顺序：移动旧库 → 建表、补列和索引 → `migrate_legacy_json` → UTC 换算。JSON 导入写进去的是本地时间，必须排在换算之前。

### 旧版本的库位置

翻看 git 历史发现，`d56b438` 到 `8288955` 之间的版本把库放在仓库根目录（`DB_PATH = Path(__file__).parent / "mcstatus.db"`），从 `a0e29c4` 开始才挪进 `data/`。用老版本的人直接 `git pull` 的话，会新建一个空库，看起来像数据全丢了。现在启动时，如果 `data/mcstatus.db` 不存在而根目录有旧库，就连同 `-wal`、`-shm` 文件一起移过去。

表结构从第一个 commit 起就没变过，只增加过 `IF NOT EXISTS` 索引。本轮新增的 `servers.icon` 列用 `ALTER TABLE` 增量添加（重复执行不会报错），另外新增 `idx_sp_name` 和 `idx_snapshots_ts` 两个索引。

### 实测

1. 用 `git worktree` 检出最老的 `d56b438`，用本项目的 venv 启动，添加 Hypixel 和 2b2t 两台真实服务器，跑了约 3 分钟，积累了 6 条快照，时间是 `17:18:28` 这样的本地时间（本机为 UTC+8）。
2. 停掉服务，原地切到 `upgrade` 分支，用 `MC_DASH_PORT=18000` 启动。日志显示旧库已移到 `data/`、已备份、已换算。`17:18:28` 变成了 `09:18:28Z`，升级后新写入的 `09:21:17Z` 和旧数据前后衔接。四个页面都返回 200，两台服务器的图标也已入库。
3. 把迁移前的备份放进 Docker 容器的 `data/` 再启动。容器系统时间是 UTC，换算结果同样是 `09:18:28Z`，说明结果不受机器时区影响。`docker compose down && up` 之后数据还在。

## 4. 速度

### 前端

原来每次打开页面，都要从 jsdelivr 下载 Tailwind 运行时，在浏览器里现场编译 CSS，再加载 Google Fonts。国内访问时，后者经常一直挂到超时。现在：

- Tailwind v4.3.3 standalone 可执行文件（放在 tools 目录）预先编译出 `static/app.css`（22KB），提交进仓库。`scripts/build_css.sh` 一行命令就能重新生成。
- `lucide@1.58.0` 和 `chart.js@4.5.1` 的 UMD 文件放在 `static/vendor/`，由 `GZipMiddleware` 压缩后传输（Lucide 455KB 压缩后约 107KB）。
- 不再加载 Google Fonts，改用系统字体：中文衬线体依次回退到 Noto Serif SC / 思源宋体 / 宋体，等宽字体依次回退到 JetBrains Mono / Cascadia Mono / Consolas。
- 顺带发现：颜色原来是写在 `<style>` 里的普通类，所以模板里的 `hover:border-ink/20`、`ring-paper-50` 这类写法从来没有生效过。现在把颜色挪进 `@theme`，`.hairline` 放进 `@layer components`，这些写法都能用了。

### 刷新

- 轮询间隔从 60 秒改为 30 秒。清理过期数据改成按时间判断（每 3600 秒一次）。
- 首页和详情页每 15 秒 `fetch` 一次当前页面，用 `DOMParser` 取出 `#live` 区域替换掉。没有新增 API，渲染逻辑全部复用 Jinja 模板。用户正在输入或页面隐藏时跳过这一轮。
- "立即刷新"表单带上 `data-ajax` 后，由 JS 后台提交。fetch 会自动跟随 303 跳转拿到新页面，再走同一个替换逻辑，后端不用改。

### 后端

用 14 天和 90 天两套演示数据压测（30 秒一条，90 天时每台服务器约 26 万条）：

| 页面（90 天库） | 改动前 | 改动后 |
|---|---|---|
| 首页 | — | 0.13–0.25s |
| 7 天历史 | — | 0.40s |
| 30 天历史，首次打开 | 1.1–2.6s | 0.94s |
| 30 天历史，翻页或切换视图 | 每次重算 | 0.04s |
| 玩家页 | 1.2s | 0.17–0.29s |

具体做了这些：

- `hourly(24)`：查询优化器原本用 `(server_id, ts)` 覆盖索引扫描了整张表，指定走 `idx_snapshots_ts` 后从 95ms 降到 19ms。
- 玩家页：原来对 30 天内所有快照跑窗口函数（587ms），改成每次出现时用索引查"同服上一条快照"的时间（39ms）。
- 名册：原来是一条 222ms 的窗口函数查询，现在直接复用 `range_history` 已经取出的数据，在 Python 里算。
- `range_history`：原来每行都跑一次 `group_concat` 相关子查询，改成两次普通查询再拼装；时间戳在 SQL 里直接转成整数秒，合并、名册、断档三个函数共用，不再各自解析。
- `history_data` 加了 `lru_cache(32)`，键是"服务器 + 时段 + 最新快照 id"，新快照一写入缓存就自然失效。只缓存合并段、名册、图表点、统计这些小结果，不缓存几万行原始数据，避免占内存。

**已知限制**：30 天视图在数据量最大时，第一次打开仍要约 0.9 秒。瓶颈是把 8.6 万行读出来转成 Python 对象（约 270ms）。再往下压，就要把合并视图和名册改成在 SQL 里计算，改动面太大，这轮没做。

### 访客延迟（L1）：没做

方案是让浏览器向 MC 端口发一个 HTTP 请求，用"被断开所用的时间"来估算延迟。先在本机校准：本机开着 Clash TUN，TCP 握手在本地就完成了，所有服务器都测出 1ms，没有参考价值。于是到美国服务器上用 Python 模拟浏览器的做法，再和纯 TCP 握手对比：

| 服务器 | TCP 往返 | 发 HTTP 到被断开 | 倍数 |
|---|---|---|---|
| hypixel | 2.3ms | 90ms | 38× |
| cubecraft | 74ms | 8082ms | 110× |
| 2b2t | 3.4ms | 14ms | 4× |
| mineplex | 3.9ms | 11ms | 3× |

断开的快慢取决于对方服务器怎么处理异常连接，有的立刻断，有的等 8 秒超时，和网络延迟没关系。浏览器又拿不到单独的 TCP 握手时间。误差远超 prompt 设定的 30%，按约定停下，为它预留的 `resolved` 列也一并删掉了。游戏内的真实 ping 需要在 MC 服务器上装插件，不在本项目范围内。

## 7. 截图

`scripts/seed_demo.py` 只用标准库，固定随机种子：

- 4 台虚构服务器，地址用 example.net / example.org 保留域名。
- 图标是 8×8 像素画放大成 64×64，用 `zlib` 直接编码成 PNG。

截图过程踩了几个坑，记下来方便以后重新生成：

- Chrome DevTools MCP 连不上浏览器，连续两次超时，改用 Chrome 命令行的 `--headless=new --screenshot`。
- Windows 上 `chrome.exe` 启动器会立即返回，截图在后台进程里稍后写出；输出重定向到 `/dev/null` 时截图会失败，必须接到管道上。
- 路径要用正斜杠：Git Bash 双引号里的 `\$1` 会被当成字面量，`\001` 这类序列也会出问题。
- Windows 窗口有最小宽度（约 500px），直接设 390 宽截出来的并不是真正的手机版式。改为用一个外壳页面嵌入 390px 宽的 iframe，截完用 ImageMagick 裁掉外壳。

截图检查中发现并修复的问题：手机端顶栏标题被挤成两行；卡片里"24h 在线"被拆开换行；表格里的状态、人数、延迟列被挤成两行；0 人在线时错误显示"服务器未公开玩家样本"或"无记录"，改为"暂无玩家在线"和"无人在线"。
